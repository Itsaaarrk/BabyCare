# Baby Care & Family Tracker

## Full Product Specification, Scope, Technical Stack, Architecture & Development Prompt

---

# 1. PROJECT OVERVIEW

Build a modern mobile application for parents, families, and caregivers to collaboratively track the daily care and activities of a baby/newborn.

The application should make recording baby activities extremely fast and simple, especially when the caregiver is busy holding or caring for the baby.

The core concept is:

> **A shared baby-care journal where everyone caring for the baby can quickly record activities and see the baby's daily routine.**

The application must support:

* Baby profiles
* Family/shared rooms
* Multiple caregivers
* Fast activity logging
* Activity timeline
* Feeding tracking
* Diaper tracking
* Sleep tracking
* Bath tracking
* Sunlight/outdoor-time tracking
* Notes
* Optional photos
* Analytics
* Daily summaries
* Family member attribution
* Customizable dashboard
* QR-code/code-based family invitations
* Notifications/reminders
* Secure Firebase-based backend

The application should NOT present itself as a medical diagnostic system.

It is a **baby care/activity tracking application**, not a replacement for professional medical advice.

---

# 2. PRODUCT NAME

Use a temporary working name during development:

**BabyCare**

The architecture should allow the application name and branding to be changed later without requiring major code changes.

---

# 3. TARGET USERS

Primary users:

* Parents
* Guardians
* Grandparents
* Nannies
* Babysitters
* Other trusted caregivers

The application should support multiple people caring for the same baby.

---

# 4. CORE PRODUCT VALUE

The application should answer these questions quickly:

1. What happened with the baby today?
2. When was the baby last fed?
3. When was the last diaper change?
4. How long did the baby sleep?
5. Who performed the activity?
6. How many activities happened today?
7. What is the baby's recent routine?
8. What did the baby do over the last 7 days?
9. Can another family member see and log the same activities?

The application should minimize typing and navigation.

# 34. SECURITY

Firebase Security Rules are critical.

Users must only access data for rooms they belong to.

Requirements:

* Users can only read authorized rooms.
* Users can only read authorized baby profiles.
* Users can only read authorized activities.
* Users cannot modify another user's account information.
* Role-based permissions must be enforced.
* Room owner permissions must be enforced.
* Viewer accounts must not create activities.
* Users cannot access photos from rooms they don't belong to.
* Users cannot manipulate membership through client-side writes without appropriate validation.

Never rely solely on frontend authorization.

Frontend authorization is for UX.

Firebase Security Rules are authoritative.

3. Implement the feature.
4. Run TypeScript validation.
5. Run relevant tests.
6. Check Firebase Security Rules where applicable.
7. Review the implementation for unnecessary complexity.
8. Report what was completed.
9. Report remaining issues.
10. Proceed to the next phase only after the current phase is stable.

Never silently skip errors.

If an architectural decision differs from this specification, explain why before implementing it.

Prioritize:

**Security → Correctness → Reliability → UX → Performance → Additional features**

Do not sacrifice security for development speed.

The final application should be production-ready in architecture, even if some advanced features are intentionally deferred from the MVP.

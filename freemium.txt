# BabyCare — Monetization, Subscription & Google Play Billing

## Development Prompt

You are the lead mobile engineer responsible for implementing the monetization and premium entitlement system for the BabyCare mobile application.

The application is a React Native + Expo + TypeScript application using Firebase Authentication, Firebase Realtime Database, Firebase Storage, and Firebase Cloud Functions.

The application is a family-oriented baby care tracker where multiple caregivers can share a Family Room and record activities such as feeding, diapers, sleep, bath, outdoor time, notes, and photos.

The goal of this task is to implement a production-ready monetization system for Google Play.

---

# 1. BUSINESS MODEL

BabyCare will use a **Freemium + Subscription + Lifetime Purchase** model.

The plans are:

| Plan         |           Price | Purpose                      |
| ------------ | --------------: | ---------------------------- |
| Free         |              ₱0 | User acquisition             |
| Plus Monthly |      ₱129/month | Flexible premium             |
| Plus Yearly  |       ₱999/year | Main paid plan               |
| Lifetime     | ₱1,999 one time | Subscription-resistant users |

The pricing must be configurable and must NOT be hardcoded throughout the application.

Create a centralized pricing/product configuration.

---

# 2. IMPORTANT BILLING PRINCIPLE

The premium entitlement belongs to the **Family Room**, not individually to every family member.

Example:

```text

"Sofia's Family"

Plan:

Billing owner:

Dad

```

All authorized members of that Family Room should receive the Premium functionality associated with that room.

Do NOT require every family member to purchase their own subscription.

This is a core product requirement.

Before implementation:

2. Determine whether the project uses Expo Go or a development/production native build.
3. Select a billing library compatible with the project's Expo architecture.

# 12. PURCHASE FLOW

When a user selects a paid plan:

1. Display the selected plan.
2. Display the price obtained from Google Play.
3. Explain the purchase.
4. Start the Google Play purchase flow.
5. Wait for purchase result.
6. Verify the purchase.
7. Update the Firebase entitlement.
8. Refresh the application state.
9. Unlock Premium features.
10. Complete/acknowledge the transaction according to Google Play requirements.

Example:

```text
Upgrade to BabyCare Plus

⭐ Best Value

₱999/year

✓ No ads
✓ Advanced analytics
✓ More photo storage
✓ Multiple babies
✓ Advanced reminders
✓ PDF reports

[ Continue ]
```

Never claim that payment succeeded before the purchase has been verified.

# 13. PURCHASE VERIFICATION

Purchase verification is a critical security requirement.

Do not trust the mobile client alone.

The recommended architecture is:

```text
Mobile App
    │
    │ Google Play purchase
    ▼
Google Play
    │
    ▼
Purchase information
    │
    ▼
Firebase Cloud Function
    │
    ▼
Verify purchase
    │
    ▼
Update Family Room entitlement
    │
    ▼
Firebase Realtime Database
```

The server-side verification mechanism should be implemented according to the current Google Play Billing requirements.

Never store Google Play service-account credentials inside the mobile application.

Never place private Google API credentials in the React Native bundle.

---

# 14. PURCHASE TOKEN SECURITY

Purchase tokens must be treated as sensitive billing information.

Do not expose purchase tokens to normal family members.

Do not place purchase tokens in logs.

Do not send purchase tokens unnecessarily between unrelated services.

Do not store service account credentials in:

* Git
* JavaScript source
* Expo configuration exposed to the client
* Firebase client configuration

Use secure server-side configuration/secrets.

* Remove Premium entitlement
* Return the room to Free
* Preserve existing user data
* Preserve existing activity history
